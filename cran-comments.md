# cran-comments

## Submission

This is a resubmission of ggnext 0.1.0, addressing the reviewer's comments
on the previous submission:

* `build_site(dir = "docs")` had a default output path, which writes to the
  user's home filespace by default. The default has been removed; `dir`
  is now a required argument, so a path must always be supplied explicitly.
  (`R/site.R`)
* `with_seed()`, an internal helper used for reproducible jitter and
  force-layout offsets, saved and restored `.Random.seed` via `globalenv()`.
  It has been replaced with `local_rng()`, a small self-contained generator
  (Park & Miller minimal-standard Lehmer PRNG) that never reads or writes
  `.Random.seed` or otherwise touches `.GlobalEnv`.
* The same replacement removes every `set.seed()` call from package code,
  including the ones building the (non-exported) gallery example data used
  by `build_site()`; that data is now generated by the same private
  `local_rng()` stream instead.
* Added `inst/WORDLIST` for the proper names and technical terms flagged as
  possibly misspelled (see Spelling below).

## Notes for the reviewer

**On the package name.** The `gg` prefix marks the shared Grammar of
Graphics lineage. `ggnext` is an independent implementation built on S7,
not a `ggplot2` extension and not affiliated with or endorsed by the
`ggplot2` authors; it does not compose with `ggplot2` objects. The README
and package documentation state this in their opening paragraphs and
credit `ggplot2` and the wider extension ecosystem as design references.

**Dependencies.** The only hard dependency is `S7`. `grDevices` and `utils`
are base packages. `testthat` and `xml2` are used only in tests.

**Writing to the file system.** No function writes anywhere by default.
`render()`, `write_plot_data()`, and `ggnext_logo()` take `file = NULL` and
return the content instead of writing when no path is given.
`build_site()`'s `dir` argument has no default and must be supplied by the
caller. Every example writes to `tempdir()`.

**Random number generation.** No package code calls `set.seed()` or
otherwise reads or writes `.Random.seed` / `.GlobalEnv`. The two layouts
that need reproducible randomness (point jitter and the force-directed
graph layout) draw from `local_rng()`, a private, self-contained generator
scoped to the call; it has no effect on R's global RNG state. This is
covered by a regression test.

**Interactive use.** Printing a plot opens a viewer only when
`interactive()` is `TRUE`.

**Spelling.** The words flagged by the incoming check are surnames from the
cited algorithm references (Bruls, Huizing, van Wijk, Fruchterman, Reingold,
Kaplan) and established technical terms (Sankey, SHAP, Scalable, treemap,
treemaps, squarified). All are spelled correctly; listed in
`inst/WORDLIST`.
